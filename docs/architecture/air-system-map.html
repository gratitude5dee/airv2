Air System Map

Every user gets a computer. The agent's memory lives on that computer's disk, and one small shared database only answers whose computer is this message for? Everything else hangs off that split. The control plane routes, meters and asks permission; the Box thinks and acts; money and publishing wait for the owner.

Overview

The four planes, and what crosses between them

Read top to bottom: a message enters through a channel, the control plane verifies and routes it, and the Box does the work. Platform-paid models and the shared connectors (Composio, WZRD Connect, MasterKey) are reached only through control-plane proxies with the Box's gateway token. Keys the owner brings (the Claude CLI, the Daytona child key, the draft-only mail key, Stripe Link, 1Password) dial their providers from the Box directly.

The Box

Sandbox security

Back to the map

The fork is the first crossing. ascii.dev forks pass noEnv: true, so the Box inherits none of the Box account's secrets; the fork env holds only TENANT_ID and GATEWAY_TOKEN, with a 24 h TTL backstop. Tenki and Namespace have no account-env inheritance. configureHermes then merges ~/.hermes/.env over the provider exec and files API. Hermes sees GATEWAY_TOKEN as OPENAI_API_KEY, with OPENAI_BASE_URL pointing at /api/gateway/v1.

  • Fork call: apps/web/lib/box/client.ts:177 (noEnv: true), TTL at apps/web/lib/box/client.ts:76; .env merge in apps/web/lib/provisioning/provision.ts:858. AIR_VAULT_KEY is minted per box and never stored in Postgres. GATEWAY_TOKEN is also in ~/.hermes/config.yaml as model.api_key (apps/web/lib/provisioning/provision.ts:948) and in ~/.openviking/ov.conf (infra/template/openviking/ovctl.py:368). The Onairos grant token and opt-in Tailscale node state also live on the Box.
  • The provider exec and files API is the most privileged way in. On ascii.dev it is POST /boxes/{id}/commands and PUT /boxes/{id}/files with BOX_API_KEY (apps/web/lib/box/client.ts:272, apps/web/lib/box/client.ts:309); on Tenki it is exec and file I/O with TENKI_API_KEY (apps/web/lib/box/tenki.ts:13); a Namespace Mac uses the control bridge (infra/template-macos/bridge.py:1). It runs a shell as user and skips _port_auth, API_SERVER_KEY and the allowlist. A leaked BOX_API_KEY is a shell on every ascii.dev Box.
  • Hermes routes: on ascii.dev, api_server and dashboard are --private routes (apps/web/lib/box/client.ts:479) and the route token travels as the _port_auth cookie (apps/web/lib/hermes/client.ts:90). Tenki exposes 8642 and 9119 as public preview URLs with no route token that live up to 30 days (apps/web/lib/box/tenki.ts:25, apps/web/lib/box/tenki.ts:83). Namespace ingress URLs carry no route token either (apps/web/lib/provisioning/provision.ts:1117). There, the URL's secrecy plus API_SERVER_KEY or basic auth is the only gate. The dashboard password is unsealed from boxes.dashboard_auth with BOX_DASHBOARD_AUTH_KEY.
  • Box proxy: apps/web/app/api/box/[...path]/route.ts:37 checks the anchored per-(method, path) allowlist in apps/web/lib/box/allowlist.ts and returns 404 before session auth. The box token is added server-side, so a browser never sees a Hermes URL. The desktop stream is the one exception: apps/web/app/api/box/desktop/route.ts:45 302-redirects the signed-in owner's own browser to their box's stream URL (a public noVNC preview URL on Tenki), with Referrer-Policy no-referrer and no-store. Only the api_server Hermes platform is enabled; infra/template/generate_platforms.py --verify fails the build otherwise.
  • Through control-plane proxies: platform-paid models and /api/mcp/*. The Composio proxy injects the org COMPOSIO_API_KEY (apps/web/app/api/mcp/composio/route.ts:49), WZRD Connect injects the user's runtime token, and MasterKey attaches the user's OAuth token, which the control plane holds. Direct from the Box: the Claude CLI (apps/web/lib/providers/claude.ts:1), the Daytona child key, the draft-only mail key, the Stripe Link CLI (apps/web/lib/payments/linkAuth.ts:26), 1Password and Bitwarden tokens, MITOSIS_API_KEY, the cal.com key (infra/template/calendar/sync.py:223) and the Kernel CDP relay to the remote cdp_url.
  • Loopback services: OpenViking 127.0.0.1:1933, taskrouter 127.0.0.1:1917, Kernel CDP relay 127.0.0.1:9222 (re-checks the owner lease on every upgrade and CDP message; the remote cdp_url bearer stays in ~/.hermes/kernel/session.json, 0600), air-learningd on a unix socket. infra/template/browser-lease-guard.sh exits 75 (fails closed) if the owner holds the checkout or Kernel human-control lease or the check fails. Vault values reach Chrome via CDP Input.insertText, never argv; the store is ~/.hermes/vault/store.enc (0600).
  • Known gap, agent uid: Hermes runs as user (infra/template/hermes-gateway.service:8) with the local terminal backend (infra/template/setup.sh:91), and user has passwordless sudo (infra/template/UPGRADE.md:111). That uid owns .env, the vault key and store, the fill-ticket directory, the Kernel session file and the real agent-browser binary (infra/template/agent-browser-guard.sh:5). The Box-side ticket check reads a JSON file and verifies no HMAC (infra/template/plugins/air-vault/fill_ticket.py:64). So the lease guard, fill tickets and vault encryption constrain the tools, not a prompt-injected shell. The GATEWAY_TOKEN authenticates about 29 control-plane routes, is readable, and egress is open. Only air-learningd is systemd-hardened (NoNewPrivileges, PrivateTmp, ProtectSystem=full).
  • Other known gaps: ascii.dev boxes have no outbound egress policy and Tenki uses allowOutbound: true (apps/web/lib/box/tenki.ts:389), so any Box process can dial anywhere. Agent Chrome runs --no-sandbox (infra/template/setup.sh:178). api_server and the dashboard bind 0.0.0.0 (infra/template/setup.sh:166, infra/template/hermes-dashboard.service:14). Opt-in Tailscale runs in userspace networking (infra/template/tailscaled.service:15), so the owner's whole tailnet reaches the 0.0.0.0 and 127.0.0.1 services without _port_auth, including OpenViking with auth_mode dev (infra/template/openviking/ovctl.py:358) and the CDP relay. During a migration the source Box serves the bundle on 0.0.0.0:8735 and the target Box dials it (infra/template/airtransfer/air_transfer.py:327). zap-light falls back to systemd-run sandboxing because ascii.dev has no /dev/kvm.

The Box

Local model router

Back to the map

The service is infra/template/taskrouter/taskrouter.py, run by infra/template/taskrouter.service as User=user with Restart=always (taskrouter.service:11) on the OpenViking venv's llama-cpp-python. It binds 127.0.0.1:1917 (taskrouter.py:306) and serves POST /route {text, trace_id?, latency_budget_ms?} and GET /health {ok, model_loaded, model_present}. The body is capped at 1 MiB and text is truncated to 4000 chars.

  • Heuristic confidence ladder: 0.9 for a deep cue or approval-worthy text, 0.7 for any tool keyword, 0.65 for under 40 chars with no signal, 0.4 otherwise. Text over 800 chars is forced to deep. Only the 0.4 rung falls under the threshold, so the model sees only medium-length messages with no keyword.
  • Model gate: heuristic confidence < 0.6 and either no latency_budget_ms or a budget of at least 3000 ms (taskrouter.py:58-60, route() at :194). An absent budget counts as enough.
  • Model: Qwen2.5-1.5B-Instruct q4_k_m, downloaded from Hugging Face at template build (infra/template/setup.sh:392-393) and loaded lazily on the first model call (taskrouter.py:66). n_ctx 2048, temperature 0, max_tokens 128, JSON-object output, observed p95 about 2.2 s. If the file is missing or fails to load, the router stays heuristics-only.
  • Validation: tier in {fast, balanced, deep}, tools a subset of {browser, filesystem, email, calendar, creative}, needs_approval a bool, confidence a number. Any deviation discards the model answer. prefetch_tools is the union of both engines' tools.
  • needs_approval is always deterministic_needs_approval() (taskrouter.py:112: side-effect verbs or payment patterns). Both engines showed payment false-negatives in eval, so the model's vote is only logged as a disagreement signal.
  • decisions.jsonl lines would hold ts, trace_id, ms, text_len, the final enums, both engines' votes and model_consulted, never the text (taskrouter.py:246). They are meant to join the learning plane by trace_id. With no caller the file stays empty, and nothing reads it.
  • Promotion gate (promotion_gate.py:33-35) on golden.jsonl (24 cases): tier accuracy at least the heuristic baseline, zero payment false-negatives, approval accuracy at least 0.85, p95 at most 3000 ms. CI calls score(cases, use_model=False) (infra/template/taskrouter/tests/test_taskrouter.py:128), which scores heuristic() directly and never runs route() or the model (promotion_gate.py:52-56). CI holds the taskrouter's heuristics to zero payment false-negatives. The model path is only scored by a manual promotion_gate.py run without --no-model. The heuristics-only run scores tier 0.667, approval 0.875 and 0 payment false-negatives, and passes.
  • Not wired: no caller of :1917 exists in apps/web, workers or Hermes plugins, so route() never runs on a real Box, the GGUF is never loaded, and the unit just idles. The repo's review default for this item is disable-taskrouter (BOX-08, CA-11, TC-30 at scripts/review-tracker.py:96), not wiring it into Hermes.
  • Gaps: the GGUF is fetched from resolve/main with no revision pin or sha256 check (infra/template/setup.sh:393), although setup.sh calls it pinned. No-egress is a code property only, since the unit sets no IPAddressDeny. The gateway's gmiRoutineTurn (apps/web/lib/gateway/routing.ts:27) mirrors the deterministic half but is separate code.

Control plane

Jev turn router

Back to the map

Jev is a typed classifier, not an executor. Its answers are rendered into a plain-text "Pre-classified routing for this turn" block; Hermes still decides and does all the work. The owner's message text (plus any attachment path markers) leaves the control plane to TypeSafe or Vercel on every routed turn.

  • Fork and join: apps/web/lib/chat/relay.ts:50 starts routeTurn without awaiting it, then awaits ensureBoxAwake (:51). The route is awaited at :70, and createRun (:72) sends the hint as instructions (:79) and as ${input}\n\n(${instructions}) (:76). Callers: apps/web/app/api/chat/route.ts:303 (web, incl. the voice trigger) and apps/web/app/api/desktop/chat/route.ts:30.
  • Backend pick (apps/web/lib/jev/transport.ts:40): TYPESAFE_API_KEY → TYPESAFE_API_BASE/v1/systemone (default https://api.typesafe.ai, model jev-latest in the body). Otherwise AI_GATEWAY_API_KEY or VERCEL_OIDC_TOKEN → AI_GATEWAY_BASE/evaluation-model (default https://ai-gateway.vercel.sh/v4/ai, header ai-model-id: typesafe-ai/jev), with noul questions retyped as boolean. Neither set → null and no network call. The backend is chosen by config on each call; a failed TypeSafe call retries TypeSafe and never fails over to the gateway (transport.ts:137-149).
  • Budget: one POST per turn, state {surface: 'air-chat', message}, each field cut to 4000 chars. Each attempt has AbortSignal.timeout(2500); a throw or non-OK status retries once (transport.ts:137, router.ts:25), so a dead backend adds about 5 s before createRun.
  • Questions and bars (apps/web/lib/jev/questions.ts:16-21, router.ts:87): capability and secondary_capability choose among 20 options (19 skills plus none). capability fires at p ≥ 0.55, or as the best non-none option when that beats p(none). secondary_capability is read only when a capability fired. Then a non-none pick other than the skill always yields a secondary, whatever its probability: below 0.55 the best non-none option replaces it only when that beats p(none) (router.ts:115-131). approval_gate chooses among 9 options at 0.6. needs_owner_context (0.6) and compound_request (0.5) are noul probabilities.
  • router.ts:192 routingInstructions returns nothing when no field fires. A gate with no skill opens that gate's owner skill (purchase_review → kernel-payments, email_draft → email-draft-review, and so on), and the gate line names the literal staging call from GATE_STAGING (router.ts:177).
  • Run paths that never see a hint: iMessage flush (apps/web/lib/orchestrator/flush.ts:1677), Create turns (lib/create/turn.ts:233), bot chats incl. web @mentions delegated before startChatRun (lib/bots/chat.ts:45), email reply runs (lib/email/inbound.ts:240), plus calendar sweep, mini-app prompt bar, muse and browser runs.
  • Mail screen (apps/web/lib/jev/mail.ts, called at lib/email/inbound.ts:176 for tier-2 senders only): state is from, subject ≤ 200 and a 400-char preview of the extracted text. spam ≥ 0.8 with transactional < 0.6 labels the message and its thread 'spam' through the provider-neutral apps/web/lib/mail/client.ts (wzrdmail by default, AgentMail only on rollback) and stops with no decision; anything else, including a null verdict, files a tier2_contact decision. needs_reply is computed but nothing reads it.

Control plane

Inference gateway and model routing

Back to the map

Code: apps/web/app/api/gateway/v1/[...path]/route.ts with apps/web/lib/gateway/{routing,metering,responses}.ts, apps/web/lib/entitlements/models.ts and apps/web/lib/providers/keys.ts. It is the only path from a Box or a Functions Worker to a model provider. Other control-plane features (creative media, voice STT, Jev) call providers directly, and Sign in with Claude never passes through it: a Claude subscription runs through the claude CLI on the Box.

  • Box-token callers are Hermes (the token is its OPENAI_API_KEY), bot profiles, the exo harness and sharedBridge's 'fast' one-liner. Box config defaults to balanced and delegation pins fast. Only 'fast' is honored from the request body, so a Box can downgrade its tier but never raise it.
  • The body is parsed between steps 6 and 7. An art_ caller must name fast, balanced or deep (air-outbound also enforces this and caps the body at 256 KiB), else 400 unknown_model. create-<tier>:<slug> must name a project with an open Create run, else 403 create_run_required.
  • Monthly cap (route.ts:283): 429 when spend ≥ monthly_cap_usd. It is skipped when GATEWAY_MODEL_FAMILY_OVERRIDE=gmi and the call is not Create, because that lane spends prepaid GMI credits.
  • gmiRoutineTurn (apps/web/lib/gateway/routing.ts:66): the last message is a user turn of at most 280 chars with no depth words (research, plan, debug and others) and no risk words (payment, transfer, publish, a dollar amount and others). gmiFastToolContinuation (routing.ts:80) also sends a tool-result continuation to fast when no user message carries a risk word. GMI_ROUTINE_FAST=off disables the routine rule.
  • Model map (models.ts:29, :43, :77, :234): GMI slugs carry a prefix (zai-org/GLM-5.3-Flash, openai/gpt-5.6-luna, openai/gpt-6-astra). gmi fast is always GLM, and the owner's gmi_model pin can replace balanced or deep. MODEL_FAST/BALANCED/DEEP and GMI_FAST/BALANCED/DEEP_MODEL re-pin tiers without touching a Box. Create defaults to GMI whatever the owner's family is.
  • Personal keys are sealed with AES-256-GCM under PROVIDER_VAULT_KEY in provider_keys and are metered at cost 0. They are skipped for art_ calls and under the fleet override. There is no personal OpenAI key; BYO ChatGPT (SIWC) serves owner chat only, never Functions, Create or the fleet override.
  • Recovery (route.ts:665-789): the 44 s GMI deadline is a header deadline shared by every GMI attempt, not a body abort. OpenAI reasoning models go through the Responses API (gateway/responses.ts) and fall back to chat/completions on 400, 404, 405 or 422. Retried statuses are 429, 500, 502, 503 and 504. A timeout that escapes every recovery returns 504.
  • Metering (metering.ts:52, :85) reads the usage chunk without altering the SSE, inserts an agent_runs row (served model, speed_tier, cost_usd, fallback_from) and calls add_spend. A Functions hold reserved at admission is settled to the real cost, or released when the stream ends without usage.

Control plane

Approval loop

Back to the map

The Box never executes a gated side effect itself. It can only create a pending row; every money, publishing and send action runs in the control plane after the owner's tap, and the decision row's conditional flip (only from pending) makes double taps and racing surfaces resolve once.

  • Gate: infra/template/setup.sh:78 seeds approvals.mode: "manual"; pinned Hermes v0.21.4 has no deny-list mode, so manual's fixed gate rules pause publishing-type tools (run state waiting_for_approval) and let everything else run.
  • Staging auth is requireBox (GATEWAY_TOKEN). The run id is looked up server-side as the user's newest agent_runs row with ended_at null (apps/web/app/api/browser/social/route.ts:70), so the box never names the run it wants resumed. A social_post with no open run is refused at approve time (apps/web/lib/decisions/resolve.ts:175).
  • Hosted link: apps/web/lib/approvals/token.ts mints HMAC-SHA256 over MINIAPP_SIGNING_KEY with use: 'approval_link' and a 15-minute TTL, as /approve/<id>?k=…. The token is never stored. app/api/approvals/[id]/route.ts accepts it or an owner session, for HOSTED_KINDS only (purchase_review, payment_request, trade_order, trade_cancel, trade_settings).
  • One resolver: /api/decisions (owner session; batch approve for email_draft only) calls resolveDecision. Hosted kinds go through resolveHostedDecision (lib/approvals/hosted.ts:239), the same function the hosted page and the trade card call. The final status update is guarded by .eq("status","pending") (resolve.ts:620).
  • Run resume: approveRun POSTs {approved} to /v1/runs/{id}/approval on the box api_server (apps/web/lib/hermes/client.ts:221). Dismiss resumes with approved=false so the agent is told no.
  • Fill tickets (apps/web/lib/vault/tickets.ts:18): exp ≤ 10 min, single use via the first insert into fill_ticket_redemptions, written to ~/.hermes/vault/.tickets/<item>.json mode 0600. Trade (lib/trade/service.ts:491) re-verifies the HMAC preview token and caps, then claims pending_approval→submitting right before the venue call. The partial unique index trade_orders_pending_idx allows one pending trade approval per user.
  • Relay failure (lib/vault/purchase.ts:308): a purchase_review approve or dismiss that cannot reach the run marks the row relay_failed and stores relay_approved. retryFailedApprovalRelays (called from app/api/cron/sweep/route.ts:182) wakes the box and retries, and closes the row if the run is gone. Other kinds, such as social_post, return 502 and stay pending for the owner to retry.
  • Trust tiers (apps/web/lib/routing/trust.ts:28): tier 0 is a verified handle, tier 1 is a sender the owner promoted, and unknown senders are recorded at tier 2. Email (lib/email/inbound.ts:172, :256): tier 0 replies auto-send, tier 1 replies are held as drafts behind an email_draft decision, and tier 2 goes through the Jev screen to a tier2_contact decision or a spam label. The control plane files these decisions itself, with no Box involved. It also files tier2_contact for unknown iMessage senders (app/api/inbound/imessage/route.ts:276) and calendar_add for .ics invites from tier 0 and 1 email senders (lib/email/inbound.ts:104). The only approval bypass is likes and reactions under a standing rule (lib/browser/rules.ts:88: daily cap counted in Postgres, refused in quiet hours).

Control plane

Inbound message lifecycle

Back to the map

Code: apps/web/app/api/inbound/imessage/route.ts (webhook), apps/web/lib/routing/spectrum.ts (signature), apps/web/lib/orchestrator/flush.ts (debounce, lanes, wake, run), apps/web/lib/orchestrator/sharedBridge.ts (first bubble and wake fallback), apps/web/lib/orchestrator/{outbound,bubbles}.ts (markers, multi-bubble) and apps/web/lib/spectrum/sender.ts. Email (Svix signature, 5-minute window, agent_addresses) and cal.com (x-cal-signature-256 HMAC, 10-minute window) follow the same order: verify, resolve, dedupe on inbound_events, return 200, then work in after(). The other two signed webhooks do not. Stripe (apps/web/app/api/inbound/stripe/route.ts:81) and the GitHub App (apps/web/app/api/inbound/github/route.ts:213) dedupe on stripe_events and github_deliveries, run their handler before answering, and return 500 when it fails so the provider redelivers (stripe/route.ts:94, github/route.ts:221). GitHub has no timestamp window.

  • Signature (spectrum.ts:12, :155): HMAC-SHA256 over v0:{timestamp}:{rawBody} with the webhook secret, compared with timingSafeEqual; a timestamp more than 5 minutes off returns 400. Signed non-conversational events (echoes, read receipts) get 200 and are ignored.
  • Early 200s with no work (route.ts:149, :207, :276): a duplicate (webhook_id, message_id) in inbound_events, an unroutable line (logged by line id only), and a tier-2 sender, which instead files a tier2_contact decision in Needs you. On the onboarding line an unknown phone number is signed up instead of dropped. Tier-0 /muse and Onairos traffic is relayed in after() and never enters batch_queue.
  • First kindness starts before the 200 (route.ts:436, :445): the tapback is dispatched and initialResponse starts racing the queue insert. The first bubble is a canned acknowledgement, an arithmetic answer or a holding line, or for short no-tool questions a 'fast' gateway call with the box's GATEWAY_TOKEN (4 s, sharedBridge.ts:27). A FINAL answer deletes that message's batch_queue row; the flush still runs to clean up. Unless the burst is an acknowledgement, a follow-up, a status check or a /draw-style media command, the flush starts a progress timeline (flush.ts:1146, ttfk.ts:248-306). It sends one status bubble 20 s after the first message, from a 'fast' completion with a 1.2 s budget (sharedBridge.ts:29) or a fixed fallback line, and stops as soon as the real reply starts streaming.
  • Debounce (flush.ts:79-88, :209): each inbound moves flush_jobs.run_at through the schedule_flush RPC. Text waits 2.5 s, media or a /draw, /freeze, /twin or creative command holds a 3 s reference window, and media plus its command together settle in 250 ms. Only the invocation whose run_at is still current claims and drains the burst. The burst's tier is its least-trusted message (flush.ts:1085).
  • Pre-wake lanes answer through the Sender and end the turn without touching the Box. An owner /create is the exception: it opens the intake and prepends a hook line, then the burst still runs in air-main. Find My holds a "near me" burst behind a location request card, or adds a fresh shared location as a context line. iMessage turns get no Jev routing hint.
  • Wake failure (flush.ts:1417-1480): the burst is carried to carried_messages and flush_jobs is rescheduled at min(15 s·2^attempts, 10 min), up to MAX_ATTEMPTS 5. Only the first attempt speaks: a sharedBridgeReply ('fast', no tools, 25 s) whose text is carried into the retried turn, or a static holding line.
  • Run (flush.ts:1505, hermes/client.ts:89): POST /v1/runs with Bearer API_SERVER_KEY and the _port_auth route cookie. Owner bursts use session air-main, others contact:<sender_id>. An owner @mention of a ready bot sends the burst to that bot's profile and chat session instead, and the streamed reply is prefixed with the bot's name.
  • Box state (boxes.ts:32, flush.ts:2048, idleStop.ts): ensureBoxAwake clears stop_after, every turn re-arms it to now + 20 min in a finally block, and the sweep stops idle boxes through the provider, never with force, deferring while OpenViking is indexing. Known gap: message text sits in batch_queue and carried_messages until drained, despite the content-free Postgres rule.

Cloudflare edge

Mini-app hosting

Back to the map

Code: apps/web/lib/miniapps/gates.ts (runGateChain), apps/web/lib/functions/handoff.ts and tokens.ts on the control plane; infra/workers/dispatcher/index.mjs, outbound/index.mjs, dev-router/index.mjs and create/src/workflow.ts at the edge. mini.wzrd.tech is the same Next.js app behind middleware.ts, which passes only /api/mini, /api/create, /api/apps and /api/store/index.json and strips client x-mini-* headers. Versions without a worker digest still render from R2 on the mini origin instead of handing off (handoff.ts:26).

  • Gates (gates.ts:273): visibility lets only published rows through (a draft loads for its owner, suspended is 404 for everyone); password checks a scrypt hash and sets a per-app proof cookie; x402 pays Base USDC to the publisher's users.wallet_address read at challenge time, and receipts are first-insert-wins on the payment nonce; session needs the per-app cookie or the owner's store session.
  • App token (tokens.ts:25): claims app, principal, role (owner, guest, anon or agent), resource, jti and exp at most 60 s out, signed with APP_ORIGIN_SIGNING_KEY. The 303 goes to <slug>-apps.wzrd.tech/__air/enter?t=….
  • Redeem once (dispatcher/index.mjs:47): one TokenReplay Durable Object per jti; its single-writer storage means two concurrent redemptions cannot both pass, which KV cannot promise. The cookie re-signs the claims with kind "c", is HttpOnly and SameSite=Lax, slides 15 minutes on every response, and the redirect lands on "/".
  • Manifest: KV key app:<slug> holding {payload, sig}, HMAC-verified with the same key, cached 60 s. Suspended or unpublished is 404; the draft script serves only an owner whose token carried draft; the dev script serves until dev_expires_at. The egress list, budget and runtime-token reference handed to air-outbound come from this manifest, and runtime.killed empties them.
  • CSP ceiling: default-src 'none', script-src 'self', img-src adds media.wzrd.tech, frame-ancestors only the mini and app origins; violation reports are counted per app per day, content-free. /api/* answers 503 functions_disabled while CREATE_FUNCTIONS_ENABLED="0" (infra/workers/wrangler.toml:27).
  • air-outbound (outbound/index.mjs:108): reads the art_ token from its own KV RUNTIME_TOKENS under rt:<ref>; no token is 403 backend_not_enabled, an oversize body 413, an unknown model 400. On air.internal routes, X-Air-* is stripped both ways and set-cookie is dropped (infra/workers/outbound/index.mjs:173). Toward an owner-approved host (https, port 443, exact hostname match), only the request's X-Air-* headers are stripped and the response is returned as-is (infra/workers/outbound/index.mjs:192). It holds no platform keys (Supabase, R2, Box, provider or signing). Only Workers dispatched by air-dispatcher pass through it, because air-dev's namespace binding attaches no outbound Worker (infra/workers/wrangler.toml:57).
  • air-create calls the control plane at /api/internal/create/* signed CF1 HMAC over "<ts>.<method>.<path>.<sha256(body)>" within ±300 s. Memory and learning

The control plane drives the Box's learning daemon by running learningctl <method> b64:… over the compute command channel (apps/web/lib/learning/learning.ts:142), with a fixed method list and params base64-encoded so no owner byte needs shell quoting. drainReceipts (learning.ts:276) peeks up to 100 receipts, keeps only the 11 allowlisted keys in RECEIPT_COLUMNS (learning.ts:254), upserts on (user_id, idempotency_key), and only then sends receipts.ack, so delivery is at-least-once.
